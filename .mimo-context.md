# Resident Management App — Context Memory

## Last Updated: 2026-05-09 (pricing snapshot per utility record)

## Architecture
- **Frontend**: Vite + React 19 + TypeScript + Tailwind CSS + PWA (port 5173)
- **Backend**: Node.js + Express + Prisma ORM + PostgreSQL (port 3002)
- **Proxy**: Vite dev proxy `/api` → localhost:3002

### 2026-05-07: Fixed push notification FK violation for residents
- **Problem**: `push_subscriptions.user_id` had FK to `users.id`, but residents authenticate via `residents` table → their ID doesn't exist in `users` → FK violation (Prisma P2003)
- **Schema fix** (`backend/prisma/schema.prisma`):
  - Removed FK relation from `push_subscriptions.user_id` to `users.id`
  - Removed `push_subscriptions[]` from `users` model
  - Added `user_type` field (`"admin"` or `"resident"`) to `push_subscriptions`
- **Controller fix** (`backend/src/controllers/pushController.js`):
  - `subscribe` now sets `user_type` based on `req.user` (admin) vs `req.resident` (resident)
- **DB**: `prisma db push` synced, `prisma generate` updated client
- **Key insight**: Residents login via `residents` table + `resident_accounts`, JWT has `{ id: resident.id, type: 'resident' }`, middleware sets `req.resident` (not `req.user`)

## API Endpoints
- `GET /api/config/amenity-limits` — Admin only (read/write config)
- `PUT /api/config/amenity-limits` — Admin only (update config)
- `GET /api/amenity-limits` — Resident auth (read-only, for portal display)
- `GET /api/amenity-usage` — Auth required (list all usages)
- `POST /api/amenity-usage` — Auth required (create booking)
- `PUT /api/amenity-usage/:id/status` — Admin/manager (update status only)
- `PUT /api/amenity-usage/:id` — Admin/manager (full edit: amenity, date, time, status)
- `DELETE /api/amenity-usage/:id` — Admin/manager (delete booking)
- `GET /api/amenity-usage/export?month=YYYY-MM` — Admin/manager (Excel download, 2 sheets)
- `GET /api/vehicles` — Admin/manager (list all vehicles with owner info)
- `POST /api/vehicles` — Admin/manager (create vehicle)
- `PUT /api/vehicles/:id` — Admin/manager (update vehicle)
- `DELETE /api/vehicles/:id` — Admin/manager (delete vehicle)
